## Claim map

**C1 — supported-path replay correctness:** Admitted recorded-token requests preserve their declared output IDs, salt isolation and ordinary-request behavior across the explicitly tested lifecycle paths. This does not assert bitwise KV equality or untested lifecycle coverage.

**C2 — scoped incremental cost:** Under a declared matched-output and matched-cache-work protocol, replay adds at most 3% end-to-end time at the stated measurement boundary and conditions. Current support is limited to the fixed 32-prompt greedy HTTP experiment; a full AgentX overhead guarantee is not established.

| Claim | Minimum convincing evidence | Existing evidence | Next block |
| --- | --- | --- | --- |
| C1 | Exact outputs and provenance; isolation; observed request lifecycle; no stale state in subsequent ordinary/replay requests | 240 original-entry requests, 447 reference requests, mixed lifecycle and cached-followup witnesses | B1 adds same-request retraction/resume and cancellation cleanup |
| C2 | Fixed prompts/outputs and observable cache work; paired end-to-end time at a declared boundary; adjusted interval upper bound at most 3% | Fixed 32-prompt greedy HTTP experiment, c1/4/8, zero retractions | No new run for current scope; B2 only for instrumented AgentX extension |

Anti-claims to rule out: cache savings are replacement-cost savings; correct returned IDs prove universal KV equality; a retraction count proves resumed replay correctness; source rows imply the same number of profiling requests; different routing implies slower GPUs. Preserve seed 42. Repeated timing runs measure execution variability of a fixed workload, not source-population or multi-seed uncertainty.

## Technical-report storyline

The main report presents opt-in integration and its exact supported-path contract, cache effects with full denominators, and separately scoped HTTP cost. The existing generated/recorded comparison is the mechanism-deletion control: same source content/scheduler configuration with substitution absent/present. Its closed-loop work mix can differ, so it is not C2's pure overhead control.

Component storage/metadata timings, warmup costs and limited MoE diagnostics support the report without adding claims. There is no trainable or frontier component to ablate. Existing post-sampling substitution is compared conceptually with established pre-sampling logit forcing, without an unsupported speed claim. No overbuilt variant needs implementation to demonstrate simplicity. Cut: new models, new MoE campaign, deterministic kernel suite, whole-KV numerical theorem and a replacement scheduler.

A controlled test-triggered retraction is permitted if it uses the pinned production retraction path. The initial test and at most one predeclared escalation must fit the 0.5 GPU-hour total ceiling. A source check alone cannot select PASS: actual request-level events are mandatory. Freeze the existing safe capacity and bounded concurrency based on the chosen complete requests. Do not truncate a real request to make it fit. If a synthetic request is needed for a lifecycle event, use and label the existing repository fixture, never count it as a real-content performance observation.

### Cases and decisive metrics

| Case | Concrete witness | Decisive pass condition | Failure/absence |
| --- | --- | --- | --- |
| L1 replay retraction/resume | Same request ID receives a partial output, is retracted, is rescheduled and continues | Observed consumed prefix survives; first resumed continuation uses the next expected ID; complete output IDs and finish reason match | Wrong index, duplicate/skipped token, stale pointer or wrong length is FAIL; no actual retraction or no observable resume is UNCOVERED |
| L2 filter/merge and mixed batch | Unequal replay lengths plus ordinary traffic; actual filter and merge events | Expected replay vectors survive metadata changes; ordinary requests complete correctly; after last replay exits, subsequent ordinary result matches ordinary reference under the same greedy conditions | Missing filter/merge event is UNCOVERED; wrong IDs/state is FAIL |
| L3 cancellation cleanup | Abort an identified in-flight replay after observed progress, before natural finish; then issue ordinary and fresh replay requests | Explicit abort terminal receipt; cancelled request cannot resume; follow-up ordinary result matches reference and fresh replay exactly matches its own IDs; observable replay state is retired | Client disconnect alone or cancelling an already finished request is UNCOVERED; state leakage/reuse is FAIL |

Use existing request-level `total_retractions` where available, but pair it with progress/resume evidence from the same request. If current diagnostics cannot expose the resume position, add the smallest test-only witness at the actual rescheduling/forward boundary, freeze and re-review that code before execution. Do not equate global retraction totals with L1. For cancellation, verify backend abort rather than assuming network disconnect implies abort.

Keep raw wire/engine events, output vectors, request IDs, sequence positions, source manifest, errors, GPU guard, command line and explicit PASS/FAIL/UNCOVERED per case in Git LFS. Diagnostics may be enabled: B1 is correctness evidence, not an overhead measurement. Read inherited cache witnesses before proposing optional logprob/cutpoint diagnostics; those diagnostics are only justified by a mismatch.

### Runtime and stopping

CPU preparation has no GPU cost. On a freshly guarded GPU0, run one ordinary reference and the bounded lifecycle cases. The entire B1 allocation, including initialization, reference, attempts, drain and teardown, is at most 30 minutes on one GPU. First attempt at most 12 minutes; at most one predeclared escalation at most 12 minutes, with up to 6 minutes reserved for initialization/cleanup. Tighten per-case timers within that envelope after code inspection; do not extend the envelope because the desired event was absent.

Stop immediately on a correctness failure and preserve artifacts. Diagnose and fix only the owning lifecycle function; a corrected code freeze needs a focused re-review and a newly recorded execution decision, not a silent extra attempt. If no decisive event occurs by the second attempt, record UNCOVERED and leave the associated C1 path unsupported. Correctness has no performance confidence interval; every admitted replay request in these fixtures must pass exact equality. This does not expand to all scheduler modes or speculative decoding.

**Table target:** a compact lifecycle matrix with trigger, event denominator, exact-ID result, cleanup result and source freeze. Do not report a pressure speedup from this diagnostic test.

## B2: instrumented AgentX cost extension, deferred

**Priority:** conditional scope expansion, not required for current HTTP C2 wording. **Current status:** DEFERRED. **Claim:** C2 only at a newly declared instrumented AgentX boundary, c1. No new GPU run is permitted by this plan alone; it first needs executable interfaces, a protocol freeze and a resource guard.

### B2-CPU gate: inherited finite-cohort semantics

Use the existing session admission cap and minimally forward it through the original InferenceX wrapper, which currently forwards duration. Avoid the request cap because its wire credits can truncate future tree turns. Before GPU work, exercise concrete scheduler objects with a CPU stub endpoint:

1. Load four qualified sequential source sessions chosen once from sorted qualified identities using seed 42. Cap profiling root admissions at four. The four loaded sessions and four admissions are separate declarations; source reuse and actual occurrences must be logged. The main B2 scope is sequential-session only because the real-content subset lacks a faithful original DAG.
2. A root active at snapshot handoff consumes exactly one profiling root admission. Its remaining turns drain. A root continuing after handoff does not consume a second credit. No fifth root is admitted or recycled into profiling after the cap.
3. Warmup can advance/recycle sessions; preserve it and log each warmup occurrence separately. Freeze the actual warmup/profiling invocation ledger. Do not assume four roots means all source rows exactly once.
4. Require sent=completed, zero errors/skips/cancellations, no pending work and normal termination. Exit code 0 alone is insufficient. Any duration/watchdog stop before the cohort drains makes the run INCOMPLETE. If DAG support is later claimed, add a parent/child/join drain fixture before broadening that scope.

Any forwarding/lifecycle change creates a new source/wheel freeze and targeted review. Do not carry the prior delivery's acceptance across the new bytes. The B2 CPU gate can fail while the current scoped report remains valid.

### B2 reference, identities and observation gate

Capture greedy outputs once while preserving all source prompt IDs, output budgets, timestamps and metadata. The trace supports one output vector per source row. If full generated occurrences for that row differ, or warmup's one-token output does not equal its prefix, the reference is incompatible: retain mismatch and stop B2. Any row used only in warmup and never observed with a complete output lacks a full reference and blocks the freeze. Do not repeatedly capture, swap sessions, drop unmatched occurrences, rewrite later prompts, or introduce occurrence-specific responses to get a passing comparison.

Persist a reference hash and ledger. Match invocations by phase, source file/row, logical root/tree occurrence, turn and reset ordinal; request IDs map to those identities. Compare salt equivalence classes because literal UUID values differ across runs. Freeze expected multiplicities and timing/arrival metadata, while retaining actual dispatch/completion times as outcomes. Same configured seed does not by itself prove ledger equality.

The original `/v1/completions` response lacks native output IDs. Use identical engine `request.finished` instrumentation in capture and both timed arms, with output IDs, request-to-source mapping and completeness receipts. Disable unrelated heavy diagnostics equally. Freeze event flush/drain handling and include required instrumentation completion in the timed boundary. If output capture cannot be made complete and symmetric, stop B2. A separate diagnostic run is not exact-output validation of the timing run. The resulting claim must explicitly say **instrumented AgentX**; it cannot certify diagnostic-free overhead.

### Work matching and measured boundary

Use the same pinned Dense model, prompt cohort, source ordering, sampler settings, seed 42, roomy capacity, snapshot/warmup, salts-as-equivalence-classes and c1 in each arm. Start each arm from the same fresh/cache-reset policy. Timer starts immediately before AgentX begins the warmup/cohort invocation and ends after all cohort requests and required observations drain. Server startup and reference capture are outside the timing comparison but included in the allocation budget and reported separately. Report warmup and profiling/drain times separately as well as their combined end-to-end total; inherit no general GPU-event timing claim.

Require equal per-invocation input/output IDs, output lengths, cache-hit/new-prefill counters and ledger multiplicities, with zero retractions/cancellations/errors. Inspect eviction and residency metrics for observable work differences; do not match by aggregate totals alone. Any mismatch invalidates the isolation analysis for the entire fixed cohort and stops the extension. Never delete mismatched requests and analyze the survivors. This is an observable-work comparison, not proof of identical internal GPU FLOPs.

### Pairs, intervals and budget

One calibration pair is excluded from inference and cannot be reused as a measured pair. Before measured pairs begin, freeze its timing receipts, remaining budget and whether five measured pairs can fit. The maximum c1 allocation is 1.5 GPU-hours total, including server startup, capture, warmup, calibration, measurements, drain and teardown. The existing approximately 40-second HTTP arm is not an estimate of AgentX runtime. If the remaining budget cannot accommodate a possible five-pair look, defer B2 without shrinking the cohort.

Measured order alternates G/R, R/G, G/R, R/G, G/R. At n=3 and, if required, n=5, compute each pair's relative time `d_i = T_recorded / T_generated - 1`; estimate `mean(d_i) ± t*sd(d_i)/sqrt(n)`. Reuse the [existing rule](../experimental/token_replay/measure_overhead.py): t=6.205347 at n=3, t=3.495405 at n=5, two prespecified Bonferroni-adjusted looks with nominal 95% simultaneous coverage under t assumptions. No intermediate significance looks or additional cohorts.

At the first look: upper bound <=0.03 supports the scoped extension; lower bound >0.03 is a valid negative; an interval crossing/touching 0.03 without already meeting the upper-bound criterion expands directly to five. At n=5: upper bound <=0.03 supports the scoped extension, lower bound >0.03 misses the target, otherwise INCONCLUSIVE. All work/ID gates must pass first. Runtime exhaustion before the required look yields INCOMPLETE, never a positive result. Negative estimates are not claimed as acceleration. No c8 or source-population inference follows from c1; a c8 extension is outside this budget and plan.

**Table target:** ledger/work-match receipt, total and phase wall times, all pair deltas and adjusted interval; explicit instrumentation and fixed-cohort scope. Keep mismatches and incomplete runs beside any valid result.
